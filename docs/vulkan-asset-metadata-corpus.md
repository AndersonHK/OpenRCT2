# Asset metadata corpus qualification

The two `AssetMetadataCorpusParityTest` cases load every available ride and peep-animation object with graphics enabled, one object at a time, against pinned original RCT1/RCT2 and bundled assets. Each actual inferred range compares its complete ordered, clipped 200×200 indexed raster against frozen `GfxDrawSpriteSoftware`, then compares the historical asymmetric bounds and production helper/load-time metadata. This is metadata/asset preparation coverage, not Vulkan screen or UI parity. Missing required original assets fail setup; no fallback artwork qualifies this corpus.

`AllAvailableRideCars` records every enabled car slot and the loader's inference-versus-prescribed-bounds contract. `AllAvailablePeepActions` covers all required actions of all animation groups and peep types, including load-time balloon/hat/umbrella height adjustments. Inputs, source object file fingerprints, per-range decoded pixel/coverage fingerprints, bounds and results are retained in `samples/AssetMetadataCorpus/*.json`. Pixel disagreements save reference/candidate/diff PNGs for required manual review; no disagreements are tolerated.

## Run 16 fixture audit

The runtime repository contained **340 ride objects and 15 peep-animation objects**. The first fixture compared **475 car ranges** with exact clipped pixels and bounds and **951 peep actions** with exact clipped pixels and bounds. The peep test passed. The ride test failed ten test-only ownership preconditions before rendering the affected ranges; it produced no pixel-divergence samples. No production defect or software exception was established.

Nine rejected objects (`rct2.ride.c3d`, `chbuild`, `circus1`, `hmaze`, `mcarpet1`, `ssc1`, and `rct2tt.ride.funhouse`, `halofmrs`, `spokprsn`) prescribe vehicle bounds with `CarEntryFlag::recalculateSpriteBounds`. Despite the historical flag name, `RideObject::Load` skips sprite inference for these cars. Some have virtual sprite counts beyond their image table. The first test incorrectly forced a helper call that the loader never makes.

The tenth object, `rct1aa.ride.lay_down_trains`, does invoke inference. Its inverted doubled image range extends beyond its own allocation. Both the frozen and new helper use the global `GfxGetG1Element` lookup and skip null elements. An object-ownership precondition is therefore stricter than the existing caller contract. This is an exposed legacy range behavior, not authorization to trim it or change production output.

Fixture version 2 corrects both test assumptions. Prescribed cases compare exact before/after load bounds and are counted separately. Actual inference preserves every requested image index; missing global entries are recorded and skipped in both oracles, while resolved foreign entries retain index, range offset, geometry/coverage metadata, decoded-content hash and registered owner/source fingerprint when available. Missing entries *inside* the loaded object's allocation remain errors. Summary counters distinguish inferred cars, prescribed cars, missing global lookups and resolved foreign lookups. No production code or pixel threshold changed. The corrected fixture awaits the coordinated rerun.

This corpus still uses the trusted asset decoder because the live sprite API lacks encoded allocation lengths. It qualifies available installed objects and reports their identities; it does not prove malformed-asset handling or all possible custom objects. Unreferenced static sprites are covered separately by the scene asset census and bounded decoder tests.

## Run 17 corrected fixture result

Both fixture-version-2 tests pass. Across 340 ride objects, **486 enabled cars** comprise **434 inferred cars** and **52 prescribed-bound cars**. The inferred ranges cover 399,758 image occurrences (not unique images), with exact clipped indexed pixels and helper/load-time bounds. All prescribed before/after bounds match. Across 15 peep objects, all **951 action/group combinations** match exact clipped pixels and inferred/accessory-adjusted bounds. There are no divergent PNG groups to inspect and no accepted exception.

The complete legacy inverted range remains in the comparison. Its **564 resolved foreign lookups**, all from `rct1aa.ride.lay_down_trains` slot 0, are range offsets 1,836–2,399, absolute global indices 134,901–135,464 in this run. Every one resolves to zero-sized metadata with no registered object owner and empty decoded bytes; none returns null. Both frozen software and the decoder produce no pixels for these entries. The report preserves each record rather than trimming the range. Missing lookup count is zero. This demonstrates parity for this concrete global allocation state; it does not prove that the legacy oversized range is independent of other loaded-object allocations. That pre-existing caller behavior remains a separate clean-up concern and is not silently corrected here.

Evidence: `obj/vulkan-parity/run-17/samples/AssetMetadataCorpus/AllAvailableRideCars.json` and `AllAvailablePeepActions.json`. The runtime object list and per-range hashes in those reports define the qualified corpus. Fixture changes corrected invalid test preconditions; production metadata code was unchanged between the failed ownership audit and this passing run.
