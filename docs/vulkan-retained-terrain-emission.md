# Retained terrain emission component

Status: **implemented and device-qualified; no admission or drawing enabled**. Build44/run38 passes775 tests. The dedicated production-no-window-terrain-emission-01 run verifies both tests and all27 samples with clean synchronization validation; [checkpoint receipts](vulkan-production-service-qualification.json) pin the build, probes and runtime evidence.

The component accepts an immutable 32x32 raw-tile snapshot with four 256-record chunks and an object-generation material table. A raw tile is 32 bytes: height, slope, grass selector, surface/edge material references and validity-kind fields. Materials contain normal image ranges and the existing 144-entry selector lookup. They contain no per-tile chosen sprites or camera-dependent commands. Material publication, loaded-object/asset census and the world snapshot producer are still integration work; the API alone does not establish their correctness.

`TerrainEmissionPipeline` borrows the existing `DeviceContext` and active `SubmissionToken`. It creates no device, window, queue or submission owner. Changed chunks and the changed material table are uploaded through the shared ring with world-category byte telemetry; unchanged/camera-only calls compare four chunk revisions and one material revision and upload zero state bytes. The publisher must issue nonzero unique revisions within each epoch and retain no mutable aliases. An epoch change or abandoned upload invalidates all cached revisions. Actual-device tests now verify old snapshots held across edits, unchanged/camera-only zero uploads, revision changes and aborted submissions.

Three dispatches use one compute shader and the reviewed `terrain_surface_rules.glsl`: validate/count each tile, scan counts into bounded offsets, then emit only if every input is valid and capacity suffices. The count scan is one invocation over 1024 records, appropriate only for this bounded foundation; it is not a scalable full-map ordering implementation. The worst allowed per-tile count fits the fixed 512-record bound. Capacity failure or invalid tile/material writes a nonzero status and zero primitive count; the emit dispatch writes no partial primitive scene. No CPU count readback or visible tile list is involved.

Output records are 64-byte **unsorted primitive descriptors**, with image address, tile index, camera-relative painter offsets and bounding-box dimensions. Rear attachments retain their base parent and reverse-prepend traversal, and front edge strips retain local bottom-to-top order. Row-major output order is deliberately not a painter key. The 48-byte status always sets `drawingQualified=0` even when descriptor emission succeeds. No `FrameExecutor`, renderer command ABI, viewport admission, software painter or default-renderer code changes are included.

Reserved map-border cells emit the frozen blank sprite at Z16 unless transparent-background is selected. This covers only the 32x32 retained domain. Frozen painting also visits blank cells outside the declared map, using camera-dependent culling and tile-origin adjustment; their complete domain is not implemented here. No drawing caller may interpret descriptor success as complete background coverage.

The qualified `VulkanRetainedTerrainEmissionTest` suite contains two actual-device tests: 22 recipe/retention samples and five invalid/capacity samples. The recipe test compares all 64 descriptor bytes against an independently compiled frozen edge/shape oracle plus current public material selection across all 16 rotation/zoom/background cases. It checks exact initial upload (35,136 bytes), unchanged/camera replay (zero), one chunk (8,192), material table (2,368), old snapshot restoration, epoch reset and abandoned recording. The error test covers zero/one-short capacity, malformed slope and overflowing material entry, then exact-capacity recovery.

Each sample retains actual GPU `before.bin` and `after.bin` for the full 8,192-record test allocation, expected descriptor bytes, a typed 48-byte status, immutable raw tile/material bytes and GPU readbacks of those raw buffers. Rejected emissions must leave the entire primitive allocation untouched. A dedicated compile receipt pins the exact shader and all ten direct implementation/oracle inputs; a dedicated no-window runner checks all 27 samples, validation activation, semantic bytes, full guards, upload sequence, runtime hashes and bounded timeout. These are staged proof mechanisms, not passing proof. General outside-map/background, full map sorting and runtime publication remain absent.

The stage introduces no production shader-list requirement. Until qualified, instantiate it only through a receipt-pinned diagnostic test using the explicit shader path. Integration must add the new C++ source to applicable renderer targets and the future test source to ordinary/no-window tests; there is no hidden fallback to another shader binary. Existing root serial builder files are not modified by this stage.
