## Frozen contract and exact raster geometry

The frozen revision is 9a092745f38a714cf33629aaa005d078d473e48b. `frozen-contract.json` pins the extracted original file to its frozen source receipt and records exact newline-normalised equality of highest-tile bounds, GetGiantViewport, and ApplyOptions in frozen/live/candidate source. The qualified frozen CLI executable must still supply image references; source equality alone is not executable provenance.

The unchanged giant viewport selects projected map corners (or existing view clipping when a real viewport is present), extends horizontal bounds by 32 world projection units on each side, selects the tallest visible element plus 64 units of top margin, and applies the requested zoom to width/height. Rotation stays masked to 0..3. The CLI's existing argument parser treats leading-minus arguments as option starts, so negative zoom giant commands are not claimed supported by this checkpoint; helper geometry is independently checked at zoom -2 through 3 for future callers. Selected Vulkan rejects out-of-range giant zoom before any invalid shift; the original software behavior remains untouched.

Tiles are row-major, at most 2048x2048 indexed pixels (4,194,304), sequential on the same service/device/pool. Full viewport width/height, world viewPos, rotation, zoom and flags are retained. Each tile viewport changes only screen pos to (-tileX,-tileY), while its target starts at (0,0). Thus ViewportPaint's world raster origin remains floorZoom(originalViewPos)+tileOutputOffset, exactly the full-image crop. No camera reconstruction, rounding, tile-local column origin, overlap blend, rescale, or hidden software rasterization is introduced. Auxiliary targets continue to bypass main presentation publication.

The final CPU indexed Image is allocated with checked size before the first session. Each tile paints through the session target's drawing engine, waits for owned output, validates identity/extents/palette/indexed byte count, copies exact rows to the final stride, and releases its session/result before the next BeginOffscreen. Any failure returns no final image, stops subsequent tiles and prevents the PNG write. An individual PNG I/O failure can still leave a partial destination file, matching existing writer behavior. GPU allocation stays bounded; CPU storage necessarily covers the exported image. Giant output does not request RGBA readback or allocate a full-sized GPU image.

PNG remains 8-bit indexed with the snapshotted game palette and the existing writer's tRNS rule (index 0 alpha 0, every other index alpha 255). Background options are unchanged. Tiles start at index 0 just like current auxiliary targets. Frozen nontransparent CreateRT leaves its initial storage uninitialised; normal terrain blank painting is expected to cover the result. Any uncovered/unstable reference bytes must be investigated and manually inspected, not waived or treated as an accepted exception.
