# Bounded custom-image segment execution (proposal only)

Source audit, 2026-09-23. The large-image design below remains unimplemented and unqualified. The separate bounded ordered alias operation is now applied and compiles in [build77](../obj/vulkan-parity/build-77/receipt.json) with zero warnings/errors; its bounded device/script regressions now pass run60 and all fifteen saved alias cases pass manual visual review. That correction does not raise the current script limit of 4,194,304 destination pixels or the independent `TextureCache::AllocateImage` source width/height limit of 2048. Raising either limit does not solve the other.

Keep `CustomImageDrawing`'s existing synchronous flush/resume boundaries. Each straight-line callback segment is recorded once; reads, nested draws and relevant source changes materialize the preceding segment before the script continues. Never replay the JavaScript callback for destination tiles. `ScreenshotTiling::Render` invokes its painter per tile and is not a drop-in script solution.

The smallest complete service extension is an indexed, unscaled 2D tiled session behind `IRenderSession`. Keep a full logical addressable recording target for existing pointer-based clipping and a full owned indexed result. Record a pointer-free ordered command tape, retaining geometry, clipping, painter depth, palette/remap/filter state and immutable source generation snapshots. Oversized source commands must be captured before the current `GetOrLoadResidentImage` atlas allocation. Sources are decoded/copied at their script-visible version; no worker-side G1 lookups or script callbacks are allowed.

Represent each large source by logical dimensions/offsets and page descriptors with source origin, actual page extent and immutable indexed/coverage bytes. Pages fit existing 2048-square atlas slots; the source descriptor is not replaced with a different whole-image atlas size. Destination tiles are at most 2048 square. Lower the relevant commands/pages into tile-local bounds and clips while retaining original source texel origin, image offsets, zoom sampling phase and line error phase. Page boundaries must not create transparency or remap seams. Script targets currently use zoom zero, but shared source machinery must explicitly preserve the BMP/RLE/zero-coverage rules rather than assuming every image treats index zero identically.

Do not pin every page of a large image at once. A conservative first implementation can partition tile execution into contiguous command-order groups as the atlas/upload budget fills. Execute each group through the existing executor with owned indexed initial contents; use its indexed readback as the next group's seed, then retire its page leases. This keeps GPU targets/residency bounded and avoids adding a persistent-canvas subsystem, at a cost of extra auxiliary readbacks. It copies bytes on CPU; it does not composite pixels there. Filter/transparency ordering must survive group boundaries. Reordering groups by asset or material is invalid.

One segment completion retains its overall identity and sources until every tile retires. Publish a script image only after the entire segment succeeds; a later tile failure must leave its previously published state intact. Nested in-place publication and subsequent seed refresh remain at existing observable boundaries. Cancellation cannot free source pages or uploads before their GPU fence. Share the configured context/device owner; do not create another device for large images.

CPU memory remains proportional to the requested output and live source versions, as required for the script's readable image buffer. Use checked dimensions and allocation failure reporting. This does not justify retaining all pages on GPU or silently changing historical maximum dimensions. Initial service admission may be explicitly indexed-only, 1:1, without lighting/native world commands because that covers this caller; other modes must not be falsely advertised.

An overlapping translated in-place self-blit has a separate aliasing requirement: the historical CPU loop can read bytes overwritten earlier in that same operation. The applied auxiliary `OrderedImageAlias` request preserves that order in a mutable GPU storage buffer using at most 8192 pixels per dispatch, with barriers between slices and at most 512 dispatches under the existing 4M-pixel cap. Its implementation and finite qualification are recorded in the [custom-image migration review](vulkan-custom-image-migration-review.md). It shares the current device and fence lifetime and introduces no CPU raster fallback. This large-image proposal must preserve that recurrence across any future pages/tiles; substituting an immutable snapshot or independently processing destination tiles is not equivalent. The bounded implementation does not establish large-image alias support.

Minimum qualification: 2049x1 source; 4097x1025 target and source; both-axis seam clips, lines, text, remaps and filters; source replacement/free after recorded use; nested same/different-image reads and writes; callback invocation counter exactly one; source generations retained through completion; failure/cancellation after an earlier tile; strict independent indexed outputs. Atlas and upload occupancy must remain bounded as dimensions increase.

Relevant source: `CustomImages.cpp` (`Begin`, `Flush`, `PrepareCustomImageSource`, `JSDrawCustomImage`), `ScGraphicsContext.hpp` (`clip`, `image`), `VulkanRenderService.cpp` (`Session`, `AuxiliaryDomain::Execute`, `BeginOffscreen`), `GpuCommandStream.h`, `GpuCommandDrawingContext.cpp`, `GpuTextureCache.cpp`, `VulkanFrameExecutor.cpp`, and `ScreenshotTiling.cpp`.
