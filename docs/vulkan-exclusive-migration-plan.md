## Outcome and migration rules

The finished game must render its main window, every viewport, previews, screenshots, and script-generated drawings through Vulkan. Software rendering must be removed from production source and build targets, rather than hidden behind a default, renamed, or retained as an offscreen fallback. Rendering-independent commands and dedicated servers must still work without a display or graphics device.

Preserve indexed assets, palette semantics, existing paint traversal and ordering, and the command recorder where useful. CPU simulation, culling, command preparation, font shaping, asset decompression, image import/export, and pixel-buffer APIs are compatible with this goal. They must not retain a general software scene/sprite compositor. In particular, merely wrapping `GfxDrawSpriteSoftware` in a function called “decode” is not removal.

Use this sequence:

1. Establish trustworthy comparisons while software remains available.
2. Close on-screen parity gaps, with narrowly documented corrections for confirmed software defects.
3. Migrate auxiliary rendering and remove hidden software dependencies.
4. Prove platform, performance, packaging, and failure behavior; make Vulkan the default.
5. Remove software and obsolete renderer-selection infrastructure; retain independent regression evidence.

Software may remain selectable during development and a bounded validation release. It is not part of the final product. Direct GPU terrain generation is an optimization, not a prerequisite for removing software: rejected direct terrain already uses CPU-prepared commands rendered by Vulkan.

## Define parity before fixing pixels

### Deterministic reference and evidence

- [ ] **T01** Freeze the accepted post-catch-up software reference commit, executable, asset hashes, fonts, config, fixture licensing/provenance, and capture tool version. Start with the deployed source/hash record above, incorporating any owner-testing fixes before producing goldens. Store portable reference images and manifests in a versioned test artifact set. Preserve the old executable externally or through repository history after deletion; do not ship or retain a test-linked software renderer in the final tree.
- [ ] **T02** Add two comparison entry points: identical low-level drawing inputs sent independently to X8 and the Vulkan recorder, and full application scenes rendered from equivalent frozen state. A command-only comparison will not detect omissions in snapshot publication or paint traversal.
- [ ] **T03** Fix simulation tick/RNG, weather phase, day/night and palette animation, entity interpolation fraction, camera/rotation/zoom, window layout, cursor/tool state, font environment, logical extent and physical extent. Freeze wall-clock-driven text/caret/notifications too. Capture through explicit test fences rather than sleeping for an estimated duration.
- [ ] **T04** Associate indexed pixels, palette, lighting, scaling parameters, world/source revision and output pixels with the same completed frame. Add generation identifiers and deterministic capture controls where absent. The ordinary latest-frame screenshot API is insufficient for selecting a named replay frame.
- [ ] **T05** Save software reference, Vulkan result, exact differing-pixel count, first mismatch, bounding box, per-channel error and an amplified diff image. Include renderer/device/driver, shader hashes and fixture state. Turn each discovered gap into a minimal regression fixture with an owner and linked fix.

### Comparison layers and pass thresholds

| Layer | Required comparison | Pass condition |
| --- | --- | --- |
| Asset preparation | Decoded indices, sprite metadata/offsets, remap/blend tables, dynamic glyph data and inferred bounds | Exact values, including transparent index semantics. Do not compare only expanded RGB: different indices may animate/remap differently later. |
| Logical rendering | Post-transparency/weather indexed canvas at fixed state, before LightFX/final colour output | Zero differing pixels outside individually approved defect cases. Compare palette values too. |
| Final SDR logical image | Palette conversion plus lighting, with fixed encoding and no physical scaling | Exact reference RGBA bytes in a controlled 8-bit target; explicitly check opaque window alpha versus transparent image output. |
| Physical SDR image | Output at drawable size for each scale-quality setting, channel order and supported surface format | Exact controlled reference output. If unavoidable driver conversion/rounding prevents equality, record the specific case and a measured numeric bound before accepting it; a global tolerance or similarity score is not sufficient. |
| Temporal behavior | Replayed construction, movement, window and lifecycle sequences | Correct frame-associated state, no stale assets/holes/tearing within a composed frame, bounded presentation latency under the performance gate. Do not compare two free-running games by wall time. |
| HDR | Explicit opt-in output and SDR fallback | Test transfer function, colour-space pair, metadata where applicable, display change and paper-white settings against a colour reference. HDR is an intentional feature variant, not a broad exemption from SDR parity. |

Read back the software SDL final target and a controlled Vulkan final-colour target. Validate actual swapchain presentation separately on representative displays; neither indexed PNGs nor human screenshots alone isolate all output stages. Preserve the existing indexed screenshot contract during migration, and provide the diagnostic colour capture separately. A user-facing “exactly what is on screen” screenshot would need a distinct colour-aware API, especially for HDR.

### Software-glitch exception ledger

Start with **zero accepted exceptions**. The user's allowance for a few software glitches does not identify which differences are legitimate.

- [ ] **T06** For each candidate, record an exception ID, reproducible fixture and state, software output, corrected expected output, root cause, evidence of intended behavior, exact affected pixels/feature, reviewer, and regression test.
- [ ] **T07** Require explicit review of the corrected result. Compare Vulkan to that result for the exception fixture, while comparing unaffected pixels exactly to software. Do not blanket-mask windows, effects, fonts or animated areas.
- [ ] **T08** Test software both with forced full redraw and with ordinary incremental rendering. A difference that disappears on full redraw is evidence to investigate a software invalidation glitch, not automatic authorization to ignore it. Keep action-sequence tests so Vulkan's own stale-state defects cannot hide behind reference corrections.

No known defect is asserted solely from a comment or an implementation difference. For example, the existing LightFX test preserving a “legacy flat clamped source stride” is a useful review candidate, not an approved bug exemption.

## Implementation work packages and gates

Assign an owner and evidence/PR links to each unchecked item when execution begins. Close a gate only when its constituent checks pass, not when a PR merely lands.

### A — Establish the baseline and support contract

- [ ] **A01** Complete T01–T08, inventory feature/setting values, and create a machine-readable gap/fixture manifest keyed by G/V IDs.
- [ ] **A02** Record currently shipped platforms and architectures from CI/distribution files, supported GPU capabilities, maximum canvas/map sizes, and rendering versus non-rendering CLI commands. Include Windows, Linux, macOS/MoltenVK and any shipped Android/web/other targets; confirm support rather than inferring it from source directories.
- [ ] **A03** Resolve Emscripten explicitly. Its current build excludes Vulkan. A retained web renderer through another API changes the “exclusive Vulkan end to end” objective; dropping an existing supported target changes feature/platform parity. Keep this as a release-blocking product decision until a compatible deployment or agreed support-scope change exists. Do not silently remove the target.
- [ ] **A04** Record capability requirements for indexed attachments, sampled integers, depth, atlas layers, storage buffers, lighting, synchronization and presentation. Distinguish requirements from optional timestamp/HDR features. Define readable startup failures and ensure non-rendering server/CLI use remains device-free.

**Gate A:** Reproducible baseline artifacts, runnable differential tests, zero unclassified exceptions, and a documented support matrix. Implementation work on independent gaps may proceed while platform decisions remain open; final removal cannot.

### B — Match the screen using the existing Vulkan command path

- [ ] **B01** Run V01–V10 and V12 against the reference. Classify each mismatch as recording/rasterization, asset preparation, presentation-state timing, final colour/scaling, or a proven software defect. Fix the smallest responsible layer.
- [ ] **B02** Implement scale-quality state and output processing for G02. Palette-expand/light the logical image before colour filtering. Match software's nearest integer upscale followed by linear filtering for smooth-nearest, including its selected intermediate size and edge behavior. Preserve nearest indexed sampling inside scene rendering.
- [ ] **B03** Complete final-colour capture and exact SDR tests for G04. Exercise sRGB and UNORM output, alpha/channel order, palette animation, light rounding/saturation and output-setting changes while packets are queued. Retain HDR as explicit opt-in.
- [ ] **B04** Resolve G11 using source revision/tick evidence. Ensure all presented map/entity state and relevant camera, UI, animation/palette/light inputs are compatible; snapshot additional inputs when necessary. Test map/entity jobs finishing in opposite orders and publication during park replacement. Preserve nonblocking routine simulation.
- [ ] **B05** Verify depth/effect ordering and resource limits for G12. - [ ] **C04** Replace X8 park/file and track-design previews; exercise load failures, all rotations, editor use and repeated prebuilt placement while the main render worker is busy. - [ ] **C05** Replace giant and CLI screenshot rendering. - [ ] **C06** Replace scripted custom-image drawing. - [ ] **C07** Replace `DummyUiContext`'s X8 factory: non-rendering tasks need no renderer; image-producing commands lazily request the offscreen Vulkan service. Audit server-side thumbnail/preview paths and separate optional graphics from simulation startup.
- [ ] **C08** Test nested auxiliary operations during main-frame recording. Resource uploads and readbacks must not deadlock the render thread or invalidate leases already recorded. Re-run V11 and relevant lifecycle tests for each migrated caller.
