## Outcome and migration rules

The finished game must render its main window, every viewport, previews, screenshots, and script-generated drawings through Vulkan. Software rendering must be removed from production source and build targets, rather than hidden behind a default, renamed, or retained as an offscreen fallback. Rendering-independent commands and dedicated servers must still work without a display or graphics device.

**Owner requirement added 2026-09-19:** the final renderer must retain assets and world rendering state in VRAM, send incremental state changes, and use shaders for expensive transforms, visibility and graphical decisions needed to place world objects correctly. It must minimize CPU work and CPU/memory/PCIe bandwidth, keep presentation effectively at the selected VSync cadence on qualified large-park workloads, and substantially increase achievable simulation TPS by freeing CPU time. Pixel parity and replacing a software framebuffer upload with a freshly CPU-painted command list are not sufficient completion criteria. The existing command recorder is migration scaffolding and an independent Vulkan comparison path until retained scene rendering is qualified. Gate P below is mandatory before default/exclusive release and removal sign-off.

Preserve indexed assets, palette semantics and the visible results of paint traversal/ordering. Preserve the command recorder where useful during migration and for bounded UI/auxiliary compatibility, while moving expensive repeated world preparation to retained GPU state and shader execution. CPU simulation, incremental state extraction, font shaping, asset decompression, image import/export and explicit pixel-buffer APIs remain valid; their measured costs must fit Gate P. They must not retain a general software scene/sprite compositor. In particular, merely wrapping `GfxDrawSpriteSoftware` in a function called “decode” is not removal.

Use this sequence:

1. Establish trustworthy comparisons while software remains available.
2. Close on-screen parity gaps, with narrowly documented corrections for confirmed software defects.
3. Migrate auxiliary rendering and remove hidden software dependencies.
4. Prove platform, performance, packaging, and failure behavior; make Vulkan the default.
5. Remove software and obsolete renderer-selection infrastructure; retain independent regression evidence.

Software may remain selectable during development and a bounded validation release. It is not part of the final product. The current narrow direct-terrain implementation is one step toward the retained GPU scene requirement. Preserve its conservative fallback during parity work, but a permanent full-world CPU paint traversal/command rebuild cannot satisfy the final performance gate merely because Vulkan rasterizes those commands.

### Software-glitch exception ledger

The original ledger began with **zero accepted exceptions**. PUBLICATION-001 now records one visually verified shared-publication defect with whole-image corrected expectations. The user's allowance for software glitches does not legitimize other differences automatically.

- [ ] **T06** For each candidate, record an exception ID, reproducible fixture and state, software output, corrected expected output, root cause, evidence of intended behavior, exact affected pixels/feature, reviewer, and regression test.

Preserve exact indexed and physical pixels throughout; every new divergence still needs agent visual inspection and a bounded disposition. The [source audit and evaluation design](vulkan-vram-state-rendering-evaluation.md) records implementation seams and expands this checklist as measurements clarify them.

- [ ] **P01** Pin repeatable workloads and numeric budgets before accepting performance changes: `EverythingPark.park`, `BigMapTest.sv6`, smaller UI-heavy parks and dense animation/lighting/transparency scenes. Record file/asset hashes, tick/seed/camera/action sequence, visible and total object/entity counts, resolution/scale, display refresh/VSync mode, CPU/GPU/driver, build/options, power state and warmup. Include moving camera, advancing simulation and edit/object-load bursts; a paused unchanged park alone cannot qualify throughput.
- [ ] **P02** Establish frozen software, present Vulkan command-stream and no-render simulation baselines. Measure CPU game-thread paint/extraction/packing time, render-worker time, allocation/copy volume, actual submitted upload bytes split by resource class, GPU pass times, queue age, presented/dropped frames and TPS. Separate first-use asset uploads, steady state, dirty bursts and explicit screenshot/export readbacks. Disable diagnostic framebuffer readback and validation in performance runs; run correctness/validation separately on the same build.
- [ ] **P03** Retain indexed assets, atlas descriptors, palettes/remap/blend tables and world/object/entity rendering records in VRAM with stable IDs and generations. Upload source asset pixels only on first residency, real content mutation or bounded eviction/reload. Track upload reasons and bytes; no full indexed/RGBA framebuffer or CPU LightFX intensity-image upload in ordinary production frames.
- [ ] **P04** Build incremental map/entity/object-state transport from real revisions/dirty records. Camera, time/animation phase, palette and weather changes update compact parameters instead of re-uploading unchanged scene records. A moving entity updates its state; unchanged tiles/assets remain resident. Test deletions, ID reuse, object reloads, park epochs, retained in-flight generations and secondary/offscreen scene isolation. Bound extraction/copy work to changed data plus measured fixed overhead.
- [ ] **P05** Move repeated world projection, sprite/world offsets, visibility and expensive animation/orientation/graphical selection to shaders reading retained state. Generate/compact draw work on GPU where needed, with indirect submission or equivalently measured bounded CPU submission. Expand by feature family only after frozen software parity: terrain/edges, tracks/supports, scenery/paths/water, vehicles, guests/staff/effects and lighting/weather. Preserve exact integer rounding, clipping, zoom, remaps, occlusion and legacy draw semantics.
- [ ] **P06** Prove ordering for intersecting objects, opaque/transparent effects and UI composition without a hidden complete per-frame CPU painter/sort. Preserve correct paint bounds/depth tie-breaking and deep overlap. Measure GPU work/memory limits and worst-case ordering cost; a GPU feature fallback still must meet the CPU/bandwidth budget and must be explicit in coverage telemetry.
- [ ] **P07** Enforce structural transport checks: warmed static view has zero scene/asset pixel uploads; camera-only motion updates parameters without world/asset rebuild; a bounded changed set produces bounded state delta bytes; palette animation changes palette data; explicit script image edits upload only changed image content. Ordinary presentation has no CPU framebuffer reconstruction, readback, GPU fence wait on the simulation thread or unbounded queue backlog. Allow asset import and requested pixel exports as separately counted operations, not loopholes for frame streaming.
- [ ] **P08** Qualify real VSync presentation over sustained runs, including at least ten minutes per representative large-park scenario after warmup. Measure actual presentation intervals/late-frame proportion plus p50/p95/p99 CPU and GPU work, rather than relying on an FPS cap/readout. Initial evaluation target: at least 99% of eligible steady-state frames meet the refresh deadline, p99 renderer CPU work under 10% of that interval, and p99 GPU work under 80%; publish stall/burst counts separately. These are explicit starting budgets, not measured results or permission to hide hitching. Lock workload/device-class budgets before final acceptance.
- [ ] **P09** Demonstrate substantial large-park TPS improvement with identical simulation behavior and real rendering enabled: report maximum sustainable TPS at the qualified display cadence, uncapped render throughput, and the no-render simulation ceiling. Quantify reclaimed renderer CPU time and the fraction of available simulation headroom recovered. Establish a numeric gain target from the measured baseline before optimization acceptance; the former allowance of a small TPS regression is insufficient. Physics-bound workloads must be identified with measurements, not used to conceal renderer overhead in render-bound parks.
- [ ] **P10** Turn byte/time/work-count limits into durable benchmark regression reports and required qualification checks. Validate representative low-end/Intel/AMD/NVIDIA/Apple targets within the declared support scope. Re-run parity, memory stability, state-update bursts and headless/offscreen behavior after GPU-state migration and from the final software-free release build.

**Gate P:** Ordinary frames render from persistent VRAM scene/assets with bounded state updates, shader-based expensive world processing, no CPU image-streaming fallback, exact qualified pixels, measured VSync pacing and substantial demonstrated large-park simulation headroom. A default toggle, GPU rasterization alone or a capped FPS counter cannot close this gate.

### E — Qualify Vulkan and make it the default

- [ ] **E01** Make Vulkan dependencies and the complete matching SPIR-V set mandatory for graphical builds. A missing SDK/build dependency or missing/stale shader must fail the build/package validation, not produce an accidental software-only binary. Preserve a supported non-rendering build configuration if needed.
- [ ] **E02** Update CMake, MSBuild projects/props/targets, test linking, shader generation/install rules, installers, CI images and platform bundles. Test clean machines with no development SDK installed; verify runtime discovery and MoltenVK packaging for declared supported targets. Use the pinned companion objects fork, materialize development junctions, verify provenance and competing IDs, and package current declarations/docs. The existing `deploy-local.ps1` takes docs from another installation and mirrors data; use the verified deployment manifest as the packaging reference until that helper is updated. Publishing the local companion pin for fresh clones remains separate work.
- [ ] **E03** Add required GPU CI lanes with explicit test counts and failure on unexpected skips. Retain ordinary helper/unit coverage for machines without GPUs, but do not count those lanes as Vulkan validation. Run validation-layer/synchronization checks and archive diagnostics.
- [ ] **E04** Test cold start, missing loader/shaders, unsupported device/format, allocation/upload exhaustion, surface loss/out-of-date/suboptimal, device loss, suspend/resume, rapid resize/minimize/fullscreen/monitor changes, and shutdown with pending readbacks. Recover when supported; otherwise report a clear error and settle waiters/resources without hanging or corrupting game state. No software renderer fallback in the final design.
- [ ] **E05** Benchmark dense EverythingPark and smaller/UI-heavy/lighting/transparency-heavy scenes on the supported low-end and representative Intel/AMD/NVIDIA/Apple hardware. Run VSync off for throughput and on for pacing. Separate simulation TPS, CPU command preparation, GPU pass times, upload/atlas behavior, memory, queue age and presented/superseded counts. Include auxiliary-output latency and repeated-load memory stability.
- [ ] **E06** Lock device/workload budgets under P01/P08/P09: actual display cadence, p95/p99 frame age and CPU/GPU costs, state/upload bandwidth, memory ceilings, offscreen dimensions/latency and substantial simulation-throughput gain. The owner's VRAM/TPS requirement supersedes the earlier provisional allowance of 5% TPS regression. No sustained memory growth after warmup; proposed budgets are not measured qualification.
- [ ] **E07** After Gates B–D and P and release qualification pass, set Vulkan as the default for fresh installs and migrate existing software/OpenGL settings to Vulkan. Test missing/invalid/legacy values and benchmark overrides. Keep software only for a time-bounded validation release if required, with a recorded exit date and outstanding blocker list.

**Gate E:** Supported release packages use Vulkan by default, parity and performance evidence pass on required hardware, and all graphics-producing auxiliary features use it. Default adoption alone is not completion.

### F — Delete software and simplify end to end

- [ ] **F01** Delete `HardwareDisplayDrawingEngine`, `X8DrawingEngine`/`X8DrawingContext`, their factory paths, and their source/header/build entries. Remove the reference backend from the final test build too; retain goldens, fixture manifests and history.
- [ ] **F02** Remove renderer selector UI, software option strings where unused, renderer-switch/recreate logic, software benchmark choices and obsolete config storage. Keep only a narrow migration reader for old config values if necessary. Do not renumber historical values into unrelated settings or break old files unnecessarily.
- [ ] **F03** Remove software-only CPU sprite/line/rectangle routines, BMP/RLE drawing templates and SIMD dispatch where now unused. Keep independently used decoding/import functionality after extraction. Verify all callers before deleting mixed-purpose files such as `Drawing.Sprite.cpp`.
- [ ] **F04** Remove retained-screen dirty grids, viewport pixel-copy/shift-strip paths, software weather restoration and dirty-region visualization. Replace any still-useful developer diagnostic deliberately. Preserve window update/layout events, image-cache invalidation and map/entity change capture: these remain necessary for correctness.
- [ ] **F05** Simplify `IDrawingEngine`/factory/backend abstractions, flags such as `dirtyOptimisations`, invalidation APIs and `CanSkipViewportInvalidation` now that there is one complete-frame renderer. Keep boundaries justified by offscreen versus windowed use, ownership and testability; do not mechanically merge all rendering into a single class.
- [ ] **F06** Remove obsolete `ENABLE_VULKAN` alternatives in graphical targets, renderer-specific SDL display code, conditional feature enablement and stale OpenGL/software instructions. Retain SDL's unrelated window/input/audio responsibilities. Keep useful CLI diagnostics identifying the active Vulkan device.
- [ ] **F07** Update the canonical architecture, build/support docs and migration notes to the final design. - [ ] **F08** Run the final independent golden suite, complete unit tests, Release builds, required GPU validation/platform lanes, interactive parity scenarios and benchmark gates from the actual software-free tree. Recheck clean install and upgrade packages; deleting code can change initialization/linking and must be validated itself.

**Gate F — exclusive renderer:** A clean checkout builds and passes all required checks without compiling or linking a software rasterizer. Every graphical product and image-producing API uses the shared Vulkan implementation. Non-rendering execution remains graphics-independent. All support-scope decisions are resolved and recorded.
