## Recommendation

Start with balloons. Paint.Balloon.cpp selects one remapped sprite from SPR_BALLOON (22651) plus `(frame & 7) + (popped != 0 ? 8 : 0)` and emits one parent with local offset `(0,0,z)` and bounds `(1,1,0)`. There are no attached children, object-manager dependencies, train links or LightFX emitter rules in this painter. The fixed G1 assets still have real dimensions, offsets and zoom metadata which must come from the accepted asset decoder, not hand-authored extents. The colour is a palette remap, not RGBA tinting.

Balloons exist naturally above the flat, surface-only terrain fixture already qualified. Litter has a small static state, but ordinary creation requires an owned above-ground path; such a park does not satisfy the current surface-only admission. Litter also has a deliberately unusual `z+4` sorting box, negative box height and direction-mask rules. Its script subtype setter is another uncovered appearance mutation. It is a useful second family after retained path templates, not the cheapest first main-screen proof.

EntityTweener::populateEntities only includes guest, staff and vehicle. Do not invent interpolated balloon motion: upload completed simulation state and let the shader select its frame. The three-tick rise, collision, RNG press behaviour, pop sound and removal remain simulation responsibilities.

## Owned records and mutation completeness

Introduce a small core presentation family record, separate from simulation layout. Proposed logical fields:

- Handle: world/entity epoch, ID, generation; present flag and monotonic family revision.
- World x/y/z as signed integers; frame, popped, colour; coarse bounds width/heightMin/heightMax needed for the existing cull contract.
- No selected sprite ID, screen position, viewport-clipped rectangle, paint-order depth or atlas UV per frame. Orientation and timeToMove do not affect this painter; retain them only in compatibility state, not GPU bytes.

Do not lock a binary layout without static_assert/offsetof and a shader layout test. The applied GPU record is 48 bytes with layout assertions. B1 transfers a dirty 64-record chunk (3,072 bytes), not a 48-byte transfer per changed entity. Asset metadata is a separate immutable table for 13 legitimate variants (eight intact and five popped), including decoded dimensions/offsets, sprite descriptor ID, zoom substitution/coordinate-shift decisions and palette mapping. Resolve/upload this table at asset residency or asset generation change. Camera/viewport/clip/visibility flags are a small per-view constant block.

Use one authoritative completed-tick fan-out of EntityVisualChangeBatch into retained family chunks. Bootstrap walks the balloon typed list once per epoch. Thereafter process changed IDs/tombstones only, and retain immutable revisions referenced by PresentationGeneration. Dirty batches must be cumulative across dropped visual packets: either packets reference durable COW chunks by revision, or a sequence acknowledged by the renderer causes a rebuild on a gap. A latest-frame mailbox must never drop the only copy of a deletion.

Do not immediately switch all entities to this dirty stream: the source audit shows appearance hooks are incomplete for other types. The bounded bridge can continue the current bulk snapshot for unconverted families while balloons have their own retained typed state. To actually remove balloon CPU page copies, EntityPresentationSnapshot needs a family-aware capture mask plus an immutable typed lookup/spatial adapter backed by retained balloon records for compatibility consumers. Returning a fake EntityBase pointer to the compact GPU struct is invalid. Either retain COW concrete Balloon values updated only on dirty events, or provide an explicit typed presentation accessor. Keep the software capture profile unchanged during qualification; compare captured canonical balloon state against the frozen live source independently. Do not change shared generation pairing or snapshot recycling rules merely for this family.

Required hooks are create-finalisation, surviving update appearance, pop, script colour mutation, existing moves/removes, and epoch reset. Reconstruct the final record at completed-tick capture; repeated marks coalesce. The ordinary timeToMove-only tick must generate no new GPU record. Creation/removal/recreation, position-to-null, script mutation while paused, import, unload and renderer restart each need a test. Observation hooks must not alter RNG, tick progression or checksum.

## GPU work and exact ordering

Use a persistent device-local family state buffer and active-ID/bucket data. Update only changed records/tombstones; reuse unchanged state across camera changes and multiple views. The submission token/resource lifetime being extracted in E3 should own uploads and fences; this is not a reason to create a new Vulkan device. Commit uploaded revisions only after successful queue submission. Abandon must leave the next submission able to reapply missed changes. Retained buffers shared by frames require queue-order/barriers; replacement buffers and atlas generations retire after the last referencing fence.

Proposed shaders and responsibilities:

1. `entity_balloon_project.comp`: select variant `(frame & 7) + 8*(popped != 0)`, apply colour remap, integer world projection, entity zoom floor, exact coarse and asset image culls; emit GPU-resident visible candidates and world bounding boxes. It reads persistent state, metadata, and view constants.
2. `entity_balloon_order.comp`: deterministic painter order for the admitted scene, emitting ordered instance indices and indirect count without host readback.
3. `entity_balloon.vert`: fetch retained/compacted data by ordered index, derive quad clipping/texel phase, use existing indexed fragment semantics and SpriteAssetDescriptor atlas origin/layer. It must not apply the terrain-specific +32 rotation adjustment from world_surface.vert to entity positions.
4. Existing indexed_rect.frag / palette / final scaling paths remain the shared pixel and display implementation; no independent RGBA balloon rasterizer.

Ordering is the principal risk. Paint.cpp uses quadrant insertion at the head, then rotation-specific CheckBoundingBox neighbour reordering. Legacy and gPaintStableSort modes differ. Entity bucket order is sorted EntityId, but reverse insertion and column tile visitation also affect ties. A `(x+y,z,id)` key or naive depth radix does not reproduce this algorithm. Parent/child/attached nodes and partial-visibility filters become additional constraints when other families join.

For a bounded exact first implementation, port the existing linked-index ordering procedure for balloon candidates within the same 32-pixel paint-column partitions; GPU integer array indices replace CPU pointers. Preserve PaintSessionGenerateRotate's tile visitation and repeated adjacent-tile encounter semantics until a separately tested simplification is proven. Candidate capacity/dispatch limits must accommodate the runtime family count, not assume 500: kMaxMiscEntities is 3200 for all ordinary miscellaneous entities, and import createEntityAt can bypass that ordinary creation admission. Overflow must select a complete legacy-rendered viewport before recording, or produce an explicit unsupported result, never silently truncate. GPU serial ordering is acceptable as a correctness prototype but requires GPU-time calibration; it is not presumed fast.

The first native admission should be an explicit, narrow whole-view contract: the already qualified flat surface-only map, only balloons as visible entity family, ordinary flags, supported assets/zoom, no map overlays or special clipping modes. Keep legacy behaviour for all excluded states. Do not weaken the existing software reference or label exclusions as parity exceptions. A balloon above a flat plane may often draw after terrain, but that is not proven by the current tests: collect baseline edge/near-ground/overlap cases first, then either demonstrate that layer composition is exact within the declared admission or include surface nodes in the GPU ordering pass. Never unconditionally draw balloons last in a general park.

Mixed guest/vehicle/path/scenery scenes remain legacy until their retained templates/order nodes enter the same scene graph. Inserting a CPU PaintStruct placeholder for each balloon to obtain its depth would preserve some pixels but retain CPU enumeration, projection/bounds and sorting; it is an explicitly temporary diagnostic comparison mechanism, not the deliverable for this family. Similarly, accepting pre-sorted CPU draw streams in the new shader would fail the VRAM-state requirement.
